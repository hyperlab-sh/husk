# Husk — Agent Instructions

Husk is a minimal, domain-agnostic TUI workbench in Go (Bubble Tea v2 + Lip Gloss v2). It only provides **slots**, **hooks** and **events**; every plugin is an independent OS process speaking newline-delimited JSON over a Unix socket (`HUSK_SOCKET_PATH`, in a private `0700` directory, socket `0600`, peer uid checked) or stdio, in any language. The layout mirrors `bb`'s 9-slot model. Husk must stay application-agnostic: nothing application-specific belongs in this repo. The docs site (docmd) is in `docs/`.

## Build & Test

```bash
go build -o bin/husk ./cmd/husk
go vet ./...
go test ./pkg/...

./bin/husk                              # run the workbench (no plugins by default)
./bin/husk --plugin-dir ./plugins       # load bundled plugins via manifests
./bin/husk --dump-frame                 # non-interactive frame dump
./bin/husk --dump-frame --rail modal    # opens the first loaded rail item with that placement; also full-canvas, stage; --hold-alt
```

Tests live in `pkg/manifest` (manifest parsing) and `pkg/frame` (frame geometry), plus `cmd/husk` host regression tests for frame resolution, sizing and rendering; run them all with `go test ./...`. Use `--dump-frame` to check rendering changes and `--demo-frame` (optionally with `--rail modal|full-canvas|stage`) to render the built-in demo plugin that declares a border+label+close frame. Surfaces are a blank canvas; all plugin-surface chrome (border/label/close) is declared by the plugin (`hello.frames` or rail-item `frame`) and drawn by `cmd/husk` `drawChrome` (`render.go`).

Golden frame tests (`cmd/husk/golden_frame_test.go`) run the real `WorkbenchModel` under `tea.Program` with `charmbracelet/x/exp/teatest/v2` (the v2 module; the unversioned path targets Bubble Tea v1), send messages, and compare the final `View().Content` with `cmd/husk/testdata/*.golden` (raw ANSI at 144x40): empty workbench, one plugin, palette open, all slots occupied. Regenerate after an intended visual change with `go test ./cmd/husk -run TestGoldenFrame -update`, then review the diff of the `.golden` files before committing. Goldens must be hermetic: use `goldenModel()` (no socket, no OS modifier poll, fixed size).

Registry, published-slot rendering/routing and protocol compatibility tests live beside their code. Run affected tests with `go test ./cmd/husk ./pkg/huskipc`; use `--dump-frame --demo pubslots` for a self-contained two-plugin frame and `--dump-frame --plugin-dir ./plugins` for rendering with external plugins (build the reference binary first: `go build -o plugins/reference/reference ./plugins/reference`). Manifest `command` paths are relative to the manifest directory (e.g. `./reference`).

The standalone v2 State package is tested with `go test -race ./internal/substrate/state/...`. Its mutations and `Get` are loop-only; other goroutines use read-only `Snapshot` values. Flush State at the end of each `Update` call, before the Event bus. The current host is not yet wired to this package.

The standalone v2 Calls package is tested with `go test -race ./internal/stem/calls/...`. Its table is loop-only and knows no message kinds; requesters receive returned results synchronously in the same `Update`, after the table mutation finishes. Configure its clock, logger and caps through `TableOptions`, separate from per-call `Options`. `Sweep()` acknowledges a sweep message; `NextSweep()` claims the single in-flight sweep slot, while `SweepCmd()` is the isolated Bubble Tea scheduling adapter. Unit tests use fake clocks/tick factories, never sleeps or real timers. The current host is not yet wired to Calls. Spec: `docs/docs/design/calls.md`.

The standalone v2 Surfaces engine (`internal/stem/surfaces`) is tested with `go test -race ./internal/stem/surfaces/...`. It serves `surface.update`, `surface.close`, `slot.contribute` and `toast.show` and owns the `husk.surfaces` resolution slice; its inputs are the Pod-written `<plugin_id>.occupants`/`<plugin_id>.contributions` declaration slices, read from snapshots and the State flush listener (declarations vs resolution, see `docs/docs/design/state.md` "Surfaces resolution"). Occupancy is first claim wins; a refused claim never takes the surface. The loop calls `Engine.Flush()` per Update: State writes happen there, never inside a listener. Clock, liveness, published-slot catalog and the Pod declaration-write seam are injected (`Options`); toasts are bounded (32, oldest dropped) with a TTL on the injected clock and never enter State. Outbound `slot.contributions` and `surface.resized` push through `contracts.Notifier` watchers (occupants only for resized). The `contracts.SurfacePort` adapter lives in `internal/host/ports/stem` (test with `go test -race ./internal/host/ports/stem/...`): it enforces the caller kinds of `contracts.MethodHomes` and maps engine refusals to `contracts.CodedError` unchanged. The current host is not yet wired to Surfaces.

Store consumes State's hooks; run `go test -race ./internal/substrate/...` for substrate changes. Store disk methods run off the loop; `Attach`, `Hydrate` and its listener do no I/O, and worker health updates use `Options.Post`. Tests inject a Clock and Keyring, plus `Options.InstanceDeps` for log-GC liveness: never use sleeps, the real OS keyring or real liveness pings. Layer documents (`keymap`) and declared focus-local bindings (`focus-keymap`) are separate APIs.

The standalone v2 process side is tested with `go test -race ./internal/pods/...`. `pods.Host` owns Pods; `pods.Loop` is the single loop-service seam. Prepare commands run off-loop and marshal State mutations back; `Host.Handle` applies lifecycle/log notices on-loop. Handle `pods.ClosedMsg` with Calls cleanup before later exit liveness. Post is worker-only, including launch/opening failures. Credentials revoke immediately on reap or channel closure while final replies drain before normal Closed; EOF/EPIPE Closed waits for Wait or the reap grace and reports the final reason. Group-empty observation fences later signals before pipe drain completes; injected 50 ms polling cancels unnecessary escalation, and SIGKILL preserves stdout through EOF or KillWait. Wrapper queue/deadline/reap-grace tests use injected clocks; process tests re-execute the test binary with an argv mode because all inherited `HUSK_*` variables (including fake-mode variables) are stripped. `EOFReapGrace` is one 100 ms default for stdout EOF and closed stdin pipes. Log paths come from the Store-owned `LogPath` seam; wrappers do not delete logs. `internal/pods/manifest.Spec` includes the full plain declaration catalog; its deep Clone, CatalogJSON and FocusKeymapJSON keep process fields out of Store declarations. Conversion validates binding ownership/scope only; Services parses keys. Plugin ids keep exact case in settings namespaces; manifest setting keys are single-segment lowercase local names, never dotted or already qualified. Conversion caps focus bindings at the first 128 entries with one too_many problem. Decoration remains pass-through boundary types. The current host is not yet wired to Pods. Spec: `docs/docs/design/pods.md`.

V2 socket/manifest changes use `go test -race ./internal/pods/... ./internal/instance/... ./pkg/protocol/...`. Server tests use private short temporary Unix socket directories, never the real runtime directory. Handler.Serve receives an explicit Notifier. Admission never blocks the reader: 64 active requests, 64 pending ordered notifications (including the active one); excess gets busy/too_many_in_flight, so EOF can cancel contexts. Socket output uses the injected queue watchdog through a write-only adapter: an injected clock's epoch is not a native socket deadline. instance.CheckRuntimeDir shares the existing directory rule; registration failure after bind is fatal. Only stale recovery takes an advisory directory-FD flock (existing gofrs/flock, O_RDONLY, no lock file), then re-probes before unlink/rebind; normal bind is lock-free. protocol.Message.HasToken distinguishes absence from a decoded empty credential. Reader diagnostics only update counters: coalesced Count/LastCode notices post from a worker at most once per second per connection, with one outstanding callback server-wide; a blocked loop never stalls readers or cleanup.

The standalone v2 Event bus is tested with `go test -race ./internal/stem/eventbus/... ./internal/host/ports/...`. `Publish`/`Flush` are loop-only (Flush at the end of each `Update`, after State); `Subscribe`, its cancel and `SetTable` are safe from any goroutine. It writes only through `contracts.Notifier` and reads liveness through an injected `Liveness` (checked at Publish). `ports/stem.Events` is the `event.emit`/`event.watch` port; its `Loop.Do` seam runs the publish on the loop. Spec: `docs/docs/design/message-kinds.md`.

The standalone v2 Dispatcher is tested with `go test -race ./internal/stem/dispatcher/... ./internal/host/ports/stem/...`. It is loop-confined: `Invoke`, `RegisterHost`, `Complete` and `List` run on the loop, and `Complete` receives the results Calls returns (Resolve, Expire, DropPlugin, Close). The catalog, liveness and focus are injected views (`DocCatalog` adapts declared `plugins` documents; `StateLiveness`/`StateFocus` read State snapshots); it never imports Store, Pods or Services. `internal/host/ports/stem.Calls` is the `CallsPort`: it posts onto the loop through an injected `Post` and waits off it. The current host is not yet wired to either. Spec: `docs/docs/design/message-kinds.md`.

Host contracts live in `internal/host/contracts` (consumer-defined ports, launch seams, `Limiter`, `Config`/`Host`, `Occupant`/`Contribution`) with recording fakes in its `fakes` subpackage; test with `go test -race ./internal/host/...`. The package must not import Services or the Server (`TestImportsStayWithinAllowList`). Ports return `CodedError`; read the wire code with `contracts.CodeOf`, never the message. Fake clocks only, no sleeps.

Services live under `internal/services/`, with shared contracts in the leaf `contracts` package and root aliases. `Rebuild(ctx, input)` prepares an unpublished candidate; only the coordinator applies it before the shared reload deadline. Public user-only exposure/mutation methods validate a verified Caller; Profile/grant writes are posted to the loop. Snapshots are immutable atomic-pointer publications. Services import no Stem/Pods or config filesystem implementation. Key spelling is shared through `internal/keyspelling`; the legacy host adopts it at switchover. Check Services with `go test -race ./internal/services/... ./internal/keyspelling/... ./pkg/theme/...`; tests inject clocks/dialogs/crypto and never sleep. A late reload request joins one queued follow-up after input capture, not an already-stale running flight. Plugin settings access (`Get` / `SnapshotFor`) is exact declared ownership plus public `husk.*`, never a subtree-prefix grant: plugin ids may contain dots and retain case; local setting keys are one lowercase segment. Caller kinds must be explicit (empty Caller is denied). Reload flight contexts belong to the coordinator, not any requester: cancelling a waiter must not cancel shared or queued work. Keymap last-good caches are profile-aware; disabled sequences never become prefixes.

## Charm v2

- Import `charm.land/bubbletea/v2` and `charm.land/lipgloss/v2`; stable v2 uses these canonical vanity paths, not the old GitHub module paths. Bubbles is not currently used.
- `View()` returns `tea.View`: use `.Content` for headless frame output/assertions, and set `AltScreen` / `MouseMode` on the view rather than program options.
- Handle `tea.KeyPressMsg` separately from `tea.KeyReleaseMsg`; mouse click, release, motion and wheel events are distinct types implementing `tea.MouseMsg` (`.Mouse()` exposes coordinates).
- Keep existing IPC key spellings through `legacyKeyString`: Space is `" "`, NUL is `"ctrl+@"`, Alt precedes other modifiers (`"alt+ctrl+x"`), and printable shifted Alt keys use their text (`"alt+X"`). Native releases may omit `Text`; normalize `ShiftedCode` too so held keys clear. Ignore Num/Scroll Lock for matching, but retain Caps Lock for printable fallback casing. Decoder-backed tests include CSI-u lock modifiers and native releases. `tea.PasteMsg` retains v1's bracket-wrapped key spelling so pasted text cannot run host shortcuts; while the palette is open the paste goes straight to the query (`pastePalette`: line breaks and tabs become spaces, other control characters are dropped).
- `lipgloss.Color` is a function returning `image/color.Color`; styles are values and there is no global renderer or `SetColorProfile`. Bubble Tea handles interactive color downsampling; headless frame dumps retain full ANSI styling.
- Use `go build -buildvcs=false` for exported-source builds and the toolchain's `gofmt` binary if a PATH wrapper does not support `-l`.

## Layout

| Path | Purpose |
| :--- | :--- |
| `cmd/husk/` | Host workbench: slots, dock/palette, mouse resize, activity rail. Files: `main.go` (flags, startup), `dumpframe.go` (`--dump-frame`: a headless `tea.Program` that settles on a quiet window capped by a maximum settle time since the surfaces were populated, plus a context deadline; no second event loop, no sleeps), `model.go` (model type, `Init`/`Update`, key-state, `modalOwner`/`surfaceOwner`), `transport.go` (accept loop, per-connection stream), `lifecycle.go` (spawn, per-plugin stderr log, exit/launch-failure reports, SIGTERM-then-kill shutdown), `input.go` (keys, mouse, drag), `commands.go` (rail buttons, palette, footer hints), `layout.go` (`recomputeLayout`, rects, frames, z-ordered hit order), `render.go` (`View` and helpers), `compose.go` (the cell canvas `View` draws into; `fillDefaultBg` paints the slot background under default-background cells), `demo.go` (`--demo-frame` / `--demo pubslots` fixtures only); `modifiers_darwin.go` polls Alt/Option via Quartz (see "Modifier polling" below) |
| `internal/substrate/state/` | V2 live JSON slice tree: owner handles, atomic copy-on-write snapshots, per-Update change listeners and preloaded Store hydration; standard library only. Initial core slice names and owners live in `initial.go`. Wire error mapping and user-only Clear authorization belong to the Server, not State. |
| `internal/substrate/store/` | V2 persistence mechanics: layered HuJSON, separate declared documents, private atomic local sources, lazy age/keyring secret namespaces, debounced retention and GC. Runtime/socket naming delegates to `internal/instance`. Secret values never go into State. |
| `pkg/huskipc/` | IPC envelope and legacy payloads (`protocol.go`, including the `FrameSpec` and `Palette` wire structs the host converts to `pkg/frame` / `pkg/theme`), published extension payloads (`published.go`), protocol version and compatibility check (`version.go`), JSON-lines reader (`read.go`: `ReadLoopReporting` reports malformed and over-4 MiB lines and keeps reading); `queue.go` is the non-blocking queued writer the host uses per connection (bounded queue, write deadline, disconnect on overflow/timeout). Never call a synchronous `NewConnWriter` from `Update` on a real connection |
| `pkg/manifest/` | `husk-plugin.json` parsing (`manifest.go`): id, name, version, language, description, command (argv, relative to the manifest dir), transport (`socket` default \| `stdio`), slots, and optional `published_slots`/`hooks`/`events` declarations (same shapes as the `hello` fields) |
| `pkg/theme/` | The single `Palette` (`Default()`): CharmTone hex roles from `charmbracelet/x/exp/charmtone`, and `SlotBackground` (`slot.go`), the slot content background derived from the canvas by a fixed Lab-lightness shift (lighter on dark, darker on light; exposed as `Palette.Slot`, wire key `slot_background`, protocol 1.2), with a WCAG contrast test (`contrast_test.go`) over every pairing the chrome draws, slot background included |
| `plugins/` | Out-of-process plugins, each a directory with a `husk-plugin.json` and its code; currently the reference pair `reference` / `reference-actions` (one Go binary in two roles: publisher with frame, inline slot, hook and event; contributor that fills the slot). Copy `plugins/reference` when starting a plugin; `plugins/reference/main_test.go` drives it over pipes, and the binary (`plugins/reference/reference`) is git-ignored. The module path is `github.com/hyperlab-sh/husk`; `pkg/huskipc` is the wire package other Go plugins import (stdlib only), so keep it stable; `pkg/theme` is host-internal and plugins receive colours as the `huskipc.Palette` wire struct |

Mouse drags start only on a drawn divider: `detectDividerAt` requires the cell to be on the border ring of a surface whose frame declares `border` and to fall in that divider's band, so the first row or column of an unbordered surface is content. Palette query input accepts any printable rune (`isPaletteText`) and backspace removes a rune. `key_state.held`/`held_keys` for ordinary keys are best effort: entries expire 320ms after the last press (`model.go`) unless the terminal confirmed key-release reporting (`View` sets `KeyboardEnhancements.ReportEventTypes` and `ReportAlternateKeys`, so a shifted symbol's release matches its press; a key held under layout text, such as AltGr's "@" or a dead key's "é", is matched to its release through `heldAliases`, because releases carry no associated text and arrive under the key-code name; `tea.KeyboardEnhancementsMsg.SupportsEventTypes()` lengthens the expiry to a 1s safety net and `KeyReleaseMsg` clears the key; `View` also sets `ReportAllKeysAsEscapeCodes` (flag 8), so where the terminal grants it Enter, Tab and Backspace releases clear immediately (`TestFlag8EnterTabBackspaceReleaseClearsHeldKey`); on a terminal that reports releases but not flag 8 they stay held until that 1s net (`TestUnreportedEnterTabBackspaceReleaseLapsesAtSafetyNet`); `ReportAlternateKeys` also fixes the chord spellings `alt+!` for Alt+Shift+1 and `ctrl+a` for Ctrl+ф, pinned by `TestKittyWireSpellingOfAlternateKeys`). The flag can fall back to false mid-session when the renderer re-queries. Under tmux, kitty flags are forwarded only on recent versions with `set -g extended-keys on`; otherwise the 320ms timer stays in charge. Only `modifiers` is authoritative.

`View` is pure: it reads the model and never writes it (`TestViewIsPure` deep-compares a rendered model with an unrendered twin). Derived UI such as the architecture explorer is built locally in the render function, never stored in `slotUpdates`; state changes belong in `Update`. `View` composes the frame on a cell canvas (`compose.go`, an Ultraviolet buffer serialized once at the end): bars, surfaces at their slot rects (reverse `hitOrder`), chrome, then the modal, toast and palette, each drawn in z order; the modal and the palette (not the toast) are each followed by `canvas.castShadow` (popup shifted +2 cols/+1 row, minus the popup, clipped; fg/bg of the cells beneath blended `popupShadowStrength` toward black, default colours resolved against Ink/Canvas, wide glyphs darkened whole, same rect once per frame). Every write parses its own string from a zero pen and is clipped to its rect, so a style a fragment leaves open stays on the cells that fragment wrote; never splice strings with `ansi.Cut` to compose. Published content is laid out (`layoutPublished`: rows, region rects, hits) and drawn separately (`publishedLayout.draw`); input routing reads only the hits. The canvas measures graphemes with `ansi.GraphemeWidth`, as the layout does, and a wide glyph crossing a clip edge is blanked. Slot content is clipped to the inner rect, never wrapped or scrolled (`surfaceContentLines`).

Layout: when the side panel is shown, `recomputeLayout` makes the header/stage rects `surfaceGutter` (1) cell narrower than the centre column and `View` leaves that cell unwritten (a blank canvas cell), so the panel starts at its own rect. The gutter is inert: it is in no slot rect, so clicks and wheel events on it reach no surface. The `sidepanel-width` divider band covers the centre's right edge, the gutter and the panel's left edge (the gutter cell itself is never a drawn border, so it starts no drag), so the drag works whichever side is bordered (`TestSidePanelDividerAcrossBorderCombinations`). The sidebar has no gutter: its rects are exactly `sidebarWidth` wide (`TestCharmV2MouseResizeLifecycle`).

Minimum terminal size is 84x24 (`minTermWidth`/`minTermHeight` in `layout.go`): below it `View` renders `renderTooSmall`, a frame that exactly fills the real terminal; `m.width`/`m.height` hold the real size and are never clamped.

Modifier polling: two sources report a bare modifier press. `View` sets `KeyboardEnhancements.ReportAllKeysAsEscapeCodes`, so kitty-protocol terminals (kitty, ghostty, wezterm, foot) send bare Shift/Ctrl/Alt/Super presses and releases as key events; `trackModifierKey` (`input.go`) folds them into `modifiers` (left and right tracked separately; Hyper/Meta dropped) and never forwards them as keys; Caps/Num/Scroll Lock presses, which terminals report only in this mode, are swallowed the same way. Because that mode stops terminals sending a key's text, `View` also sets `ReportAssociatedText`: text keys arrive as CSI-u with the produced text as a parameter, so AltGr symbols and dead-key or compose results keep their text (the key code alone would give the unshifted base key). `legacyKeyString` drops associated text from Ctrl/Super/Meta/Hyper chords so their names are unchanged, and `normalizeTextEvent` turns the spec's key-0 "pure text event", which the pinned decoder reads as ctrl+space, back into text. Bracketed paste is framed by the paste mode, not the keyboard flags. IME commits bypass the key encoder in kitty, foot and wezterm (plain UTF-8); ghostty sends them as plain UTF-8 or as CSI-u with associated text. That reading comes from the terminals' source, not from a session with a real input method. On darwin the OS modifier poll (`pollOSModifiers`) is also authoritative and overwrites the state on each tick; it is the only source on terminals without the protocol (Terminal.app, tmux). The poll runs every 40ms while a modifier, held key or input from the last 2s is active, every 150ms when idle, and not at all while the terminal is blurred. `View` sets `ReportFocus`, so `tea.BlurMsg` clears OS- and terminal-derived modifiers and held keys (broadcasting `key_state` up; a latched Alt from `?` or `--hold-alt` survives) and lets the tick chain lapse; `tea.FocusMsg` restarts it. Terminals without focus reporting never send `BlurMsg` and keep polling (under tmux, `set -g focus-events on` is required for blur gating). Where no OS modifier source exists (non-darwin), the chain lapses once no held key is pending and restarts on the next key press. Idle cost on darwin: a tick is about 0.32ms (the `View` rebuild dominates; the poll is about 31ns), so the 150ms idle rate is about 0.2% of one core; `BenchmarkIdleTickView` reproduces it.

Enumerated wire fields are named types with `Valid()`/`Validate()` in `pkg/huskipc/wirevalid.go` (`SlotID`, `KeyPhase`, `RailPlacement`; `KeyStatePayload`, `SlotKeyPayload`, `RailItemSpec`); they marshal as plain strings, so the JSON is unchanged. Use the `huskipc.KeyPhase*` constants, not string literals.

IPC messages: `hello`/`welcome`, `slot_update`, `slot_resize`, `slot_key`, `slot_mouse`, `key_state`, `workspace_context`, `command_invoke`, toasts, `protocol_error`. Plugin placements: `modal`, `full-canvas`, `stage`.

Protocol versioning: `hello.protocol_version` / `welcome.protocol_version` are `"MAJOR.MINOR"` (`huskipc.ProtocolVersion`). A hello with a different major or an unparsable version is rejected with `protocol_error` and closed; an absent version is a pre-versioning plugin (major 1). Minor bumps are additive only. Malformed JSON, mistyped fields, lines over 4 MiB, missing or unknown `type` and missing payloads are answered with `protocol_error` and logged; the connection stays open. The host never answers a plugin's `protocol_error`. `pkg/huskipc` imports the standard library only (`TestWirePackageImportsStandardLibraryOnly`). The wire JSON Schema `docs/docs/wire-schema.json` is generated from the structs (`pkg/huskipc/schema`, `cmd/genschema`): run `go generate ./pkg/huskipc` after any wire type change; `TestCommittedSchemaIsCurrent` fails when stale. Spec: `docs/docs/architecture.md` "Versioning" and "Errors".

The independent v2 wire package is `pkg/protocol` (standard library only); the current host remains on `pkg/huskipc` until the later switchover. After a v2 wire type change, run `go generate ./pkg/protocol` to refresh `docs/docs/wire-schema-v2.json` via `cmd/genschema-v2`; do not overwrite the v1 schema. Run affected tests with `go test ./pkg/protocol/...`. Queue tests inject `QueueOptions.Clock` rather than sleeping or using real timers. Spec: `docs/docs/design/protocol.md`.

Hook calls expire: a subscriber silent for 10s (`hookTimeout`) is answered for with a `hook_result` carrying `error: "timeout"`; pending calls are capped at 1,024 overall and 64 per subscriber (`registry.go`; a `hookSweepMsg` tick runs only while calls are pending). `declareNamedInfo` keeps hook/event `title`/`description`; `describe` lists them. Spec: `docs/docs/architecture.md` "Hooks".

A plugin that stops reading is disconnected (queue of 1,024 messages, 5s write deadline), never waited on; every disconnect reason (EOF, read error, write timeout, queue overflow) is logged and toasted, and a connection that closes before a registered hello is logged too. Policy: `docs/docs/architecture.md` "Outbound queue and disconnect policy".

Manifest enforcement: for plugins launched from a `husk-plugin.json`, `pkg/manifest` `Plugin.CheckHello` requires `hello.plugin_id` == manifest `id` (bound for stdio streams and for socket peers whose kernel pid is a live launched process or a descendant of one, so a plugin a wrapper script started is bound to the wrapper's manifest; `launchedID` walks the peer's ancestry with `peerAncestry`/`parentPID` (`procparent_*.go`: `/proc/<pid>/stat` on Linux, `kern.proc.pid` sysctl on macOS), nearest launched ancestor wins; other socket peers, including a detached daemon reparented to init, are checked only against the manifest named by the id they claim) and `hello.slots` == manifest `slots` (as sets); the host runs it first in `pluginRegisteredMsg` (`checkManifest`) and rejects with `protocol_error` + close. `launchPlugin` rejects a duplicate plugin id. Manifest `published_slots`/`hooks`/`events` are registered by `launchPlugin` (`registry.declareFromManifest`, atomic, same namespace validation, region surfaces checked against the manifest's `slots`) before the plugin connects and flagged `FromManifest`; a hello may repeat them (empty fields defer, set fields must match, else `protocol_error`) via `declareSlotFromHello`/`declareNamedFromHello`. A launched process that exits without a registered connection drops them, except a socket process that exited 0 (`pluginExitedMsg.handedOff`, a launcher that started the real plugin), which keeps them for the later `hello` for at most `pluginHandoffGrace` (30s; `handoffGrace` on the model, `handoffExpiredMsg` fires it, `handoffPending` marks the ids still waiting and a registered hello clears the mark), after which they are dropped like a failed exit. That exit raises an info toast, not the warn one. `manifest.splitCommand` is shell-style (quotes, backslash) and errors on unterminated quotes.

Plugin processes (`lifecycle.go`, policy in `docs/docs/architecture.md` "Plugin processes"): stderr goes to `logs/<id>.log` in the socket directory; `HUSK_SOCKET_PATH` is exported only for socket transport and stripped for stdio; launch failures, unexpected exits (status plus stderr tail), accept failures and pre-hello traffic (`protocol_error`) are logged and toasted. Background goroutines never call `logf`; they `post` a message and `Update` logs it. Shutdown (`cleanup`, idempotent, run by `main` after the program exits) closes `quit`, sends SIGTERM, waits `stopGrace` (2s), then kills and waits. `lifecycle_test.go` re-executes the test binary as a fake plugin (`HUSK_FAKE_PLUGIN`).

## Conventions

- Husk core stays domain-agnostic: application-specific logic belongs in a plugin, not in `cmd/husk`. The host hard-codes no plugin command or rail item ID, no application key, and no application colour; keys reach plugins through rail item `shortcut`s, `hello.keybindings` and focused-surface `slot_key` (see `docs/docs/architecture.md`, "Input routing"). `TestHostSourceHasNoApplicationIdentifiers` guards the source and `TestDocsHaveNoApplicationResidue` guards the docs (README, SUMMARY, AGENTS, `docs/docs/*.md`), including that the documented surface count matches the registry.
- Plugins are launched only via `--plugin` (executable, plugin dir, or `husk-plugin.json`) or `--plugin-dir` (scans immediate subdirectories). There is no default plugin.
- Plugins must never assume a language; the JSON-lines protocol is the only contract. Additive changes (new optional fields or message types) bump the minor of `huskipc.ProtocolVersion`; anything else is a major bump, which the host rejects for older plugins, so it means updating `pkg/huskipc` and every plugin.
- Colour comes only from `theme.Default()`, whose roles are CharmTone hex values (truecolor; lipgloss downsamples on weaker terminals). Do not add other themes or literal colours in the host. Changing a role must keep `TestDefaultPaletteContrast` green (text 4.5:1, borders and non-text 3:1). `charmtone` is `x/exp` with a single v0.1.0 tag, so pin it.
- Conventional commits with detailed messages. No attribution trailers.
- `SUMMARY.md` is the design history; `README.md` is user-facing.

## Beads Issue Tracker

This project uses **bd (beads)** for issue tracking. The database is shared with a sibling project (Husk issues use the `husk-` prefix). Run `bd prime` to see full workflow context and commands.

### Quick Reference

```bash
bd ready              # Find available work
bd show <id>          # View issue details
bd update <id> --claim  # Claim work
bd close <id>         # Complete work
```

### Rules

- Use `bd` for ALL task tracking — do NOT use TodoWrite, TaskCreate, or markdown TODO lists
- Run `bd prime` for detailed command reference and session close protocol
- Use `bd remember` for persistent knowledge — do NOT use MEMORY.md files

**Architecture in one line:** issues live in a local Dolt DB; sync uses `refs/dolt/data` on your git remote; `.beads/issues.jsonl` is a passive export. See https://github.com/gastownhall/beads/blob/main/docs/core-concepts/sync-concepts.md for details and anti-patterns.

## Agent Context Profiles

The managed Beads block is task-tracking guidance, not permission to override repository, user, or orchestrator instructions.

- **Conservative (default)**: Use `bd` for task tracking. Do not run git commits, git pushes, or Dolt remote sync unless explicitly asked. At handoff, report changed files, validation, and suggested next commands.
- **Minimal**: Keep tool instruction files as pointers to `bd prime`; use the same conservative git policy unless active instructions say otherwise.
- **Team-maintainer**: Only when the repository explicitly opts in, agents may close beads, run quality gates, commit, and push as part of session close. A current "do not commit" or "do not push" instruction still wins.

## Session Completion

1. **File issues for remaining work** - Create beads for anything that needs follow-up
2. **Run quality gates** (if code changed) - build, `go vet`, `--dump-frame` checks
3. **Update issue status** - Close finished work, update in-progress items
4. **Handle git/sync by active profile** - report `git status` and proposed commands; wait for approval
5. **Hand off** - Summarize changes, validation, issue status, and any blocked sync/commit/push step

**Critical rules:**
- Explicit user or orchestrator instructions override this Beads block.
- Do not commit or push without clear authority from the active profile or the current user request.
- If a required sync or push is blocked, stop and report the exact command and error.
