# Husk — Agent Instructions

Husk is a minimal, domain-agnostic TUI workbench in Go (Bubble Tea v2 + Lip Gloss v2). It only provides **slots**, **hooks** and **events**; every plugin is an independent OS process speaking newline-delimited JSON over a Unix socket (`HUSK_SOCKET_PATH`, in a private `0700` directory, socket `0600`, peer uid checked) or stdio, in any language. The layout mirrors `bb`'s 9-slot model. Husk must stay application-agnostic: nothing application-specific belongs in this repo. The docs site (docmd) is in `docs/`.

## Build & Test

```bash
go build -o bin/husk ./cmd/husk
go vet ./...
go test ./pkg/...

./bin/husk                              # run the workbench (no plugins by default)
./bin/husk --plugin-dir ./plugins       # load bundled plugins via manifests
./bin/husk --dump-frame                 # non-interactive frame dump
./bin/husk --dump-frame --rail modal    # opens the first loaded rail item with that placement; also full-canvas, stage; --hold-alt
```

Tests live in `cmd/husk` (host regression tests for frame resolution, sizing, rendering and the Frontend seam, on a recording fake in `testkit_test.go`) and `pkg/frame` (frame geometry); the v2 packages carry their own tests. Run affected packages with `go test ./cmd/husk ./pkg/frame`. Use `--dump-frame` to check rendering changes and `--demo-frame` (optionally with `--rail modal|full-canvas|stage`) to render the built-in demo plugin that declares a border+label+close frame. Empty region slots show their humanised surface name; occupied surfaces are a blank canvas until their occupant draws. All plugin-surface chrome (border/label/close) is declared by the plugin (a `frame` on a manifest `surfaces` entry or on a rail item) and drawn by `cmd/husk` `drawChrome` (`render.go`).

Golden frame tests (`cmd/husk/golden_frame_test.go`) run the real `WorkbenchModel` under `tea.Program` with `charmbracelet/x/exp/teatest/v2` (the v2 module; the unversioned path targets Bubble Tea v1), send messages, and compare the final `View().Content` with `cmd/husk/testdata/*.golden` (raw ANSI at 144x40): empty workbench, one plugin, palette open, all slots occupied. Regenerate after an intended visual change with `go test ./cmd/husk -run TestGoldenFrame -update`, then review the diff of the `.golden` files before committing. Goldens must be hermetic: use `goldenModel()` (no socket, no OS modifier poll, fixed size).

Published-slot rendering and routing tests live beside their code (`published_*_test.go`); use `--dump-frame --demo pubslots` for a self-contained two-plugin frame and `--dump-frame --plugin-dir ./plugins` for rendering with the reference plugins (build the binary first: `go build -o plugins/reference/reference ./plugins/reference`). Manifest `command` paths are relative to the manifest directory (e.g. `./reference`).

The standalone v2 State package is tested with `go test -race ./internal/substrate/state/...`. Its mutations and `Get` are loop-only; other goroutines use read-only `Snapshot` values. Flush State at the end of each `Update` call, before the Event bus. `internal/host.New` wires it; `cmd/husk` drives it through `Host.Frontend()`.

The standalone v2 Calls package is tested with `go test -race ./internal/stem/calls/...`. Its table is loop-only and knows no message kinds; requesters receive returned results synchronously in the same `Update`, after the table mutation finishes. Configure its clock, logger and caps through `TableOptions`, separate from per-call `Options`. `Sweep()` acknowledges a sweep message; `NextSweep()` claims the single in-flight sweep slot, while `SweepCmd()` is the isolated Bubble Tea scheduling adapter. Unit tests use fake clocks/tick factories, never sleeps or real timers. `internal/host.New` wires it; `cmd/husk` drives it through `Host.Frontend()`. Spec: `docs/docs/design/calls.md`.

The standalone v2 Surfaces engine (`internal/stem/surfaces`) is tested with `go test -race ./internal/stem/surfaces/...`. It serves `surface.update`, `surface.close`, `slot.contribute` and `toast.show` and owns the `husk.surfaces` resolution slice; its inputs are the Pod-written `<plugin_id>.occupants`/`<plugin_id>.contributions` declaration slices, read from snapshots and the State flush listener (declarations vs resolution, see `docs/docs/design/state.md` "Surfaces resolution"). Occupancy is first live claim wins: a claim counts only while its Pod is `live` (the host calls `Engine.LivenessChanged` on every `husk.pods` write; a Pod that leaves `live` gives the surface to the next live claimant in namespace order, a live occupant is never preempted), and a refused claim never takes the surface. The loop calls `Engine.Flush()` per Update: State writes happen there, never inside a listener. Clock, liveness, published-slot catalog and the Pod declaration-write seam are injected (`Options`); toasts are bounded (32, oldest dropped) with a TTL on the injected clock and never enter State. Outbound `slot.contributions` and `surface.resized` push through `contracts.Notifier` watchers (occupants only for resized). The `contracts.SurfacePort` adapter lives in `internal/host/ports/stem` (test with `go test -race ./internal/host/ports/stem/...`): it enforces the caller kinds of `contracts.MethodHomes` and maps engine refusals to `contracts.CodedError` unchanged. `internal/host.New` wires it; `cmd/husk` drives it through `Host.Frontend()`. `Engine.UpdateView` writes the frontend half of `husk.surfaces` (visible, placement, overlays) and the host pushes `Engine.Resized` after each tick from the frontend's `husk.geometry`/`husk.focus`/view writes, deduped.

Frontend seams (`contracts.Frontend`, returned by `Host.Frontend()` and implemented by the `internal/host` root; implementation in `internal/host/frontend.go`, tests with `go test -race ./internal/host/`): State snapshot, Theme palette, Keybinding `Resolve`/`Hints`/`KeysFor`, `InvokeAction` as the Stem, `RegisterHostAction`, `SendKey`/`SendMouse`/`SendKeyState` to a live Pod, `RailItems`, `PublishedSlots`, `SurfaceFrames` and `Actions` from the declared `plugins` documents (cached per `Store.DeclaredRevision`; `Looped.Planned()` is the plugin count a headless run waits for), `ActiveToast` (the Surfaces engine's toast queue; loop-only), `Refusals` (plugins refused before a Pod existed; the frontend toasts each once), `OwnSlices` (owner handles of `husk.layout`/`geometry`/`focus`, once) and `UpdateSurfaceView`. Each method documents whether it is loop-only; a frontend that wrote State without posting a host message calls `host.Looped.Tick()` at the end of its Update so the write flushes. `Config.Content` is the content sink: the Surface port calls it on the loop only after the engine accepts a `surface.update`. Manifest `rail_items[]` (v2 only) are validated in `internal/pods/manifest`; a rail item `shortcut` becomes a `suggestion_ignored` problem. Spec: `docs/docs/design/pods.md` "Frontend seams".

Store consumes State's hooks; run `go test -race ./internal/substrate/...` for substrate changes. Store disk methods run off the loop; `Attach`, `Hydrate` and its listener do no I/O, and worker health updates use `Options.Post`. Tests inject a Clock and Keyring, plus `Options.InstanceDeps` for log-GC liveness: never use sleeps, the real OS keyring or real liveness pings. Layer documents (`keymap`) and declared focus-local bindings (`keymap`, D64) are separate APIs.

The standalone v2 process side is tested with `go test -race ./internal/pods/...`. `pods.Host` owns Pods and publishes `pods.plugin-exited` through `Options.Publisher` when a Pod exits or fails; `pods.Loop` is the single loop-service seam. Prepare commands run off-loop and marshal State mutations back; `Host.Handle` applies lifecycle/log notices on-loop. Handle `pods.ClosedMsg` with Calls cleanup before later exit liveness. Post is worker-only, including launch/opening failures. Credentials revoke immediately on reap or channel closure while final replies drain before normal Closed; EOF/EPIPE Closed waits for Wait or the reap grace and reports the final reason. Group-empty observation fences later signals before pipe drain completes; injected 50 ms polling cancels unnecessary escalation, and SIGKILL preserves stdout through EOF or KillWait. Wrapper queue/deadline/reap-grace tests use injected clocks; process tests re-execute the test binary with an argv mode because all inherited `HUSK_*` variables (including fake-mode variables) are stripped. `EOFReapGrace` is one 100 ms default for stdout EOF and closed stdin pipes. Log paths come from the Store-owned `LogPath` seam; wrappers do not delete logs. `internal/pods/manifest.Spec` includes the full plain declaration catalog; its deep Clone, CatalogJSON and KeymapJSON keep process fields out of Store declarations. Conversion validates binding ownership/scope only; Services parses keys. Plugin ids keep exact case in settings namespaces; manifest setting keys are single-segment lowercase local names, never dotted or already qualified. Conversion caps focus bindings at the first 128 entries with one too_many problem. Decoration remains pass-through boundary types. `plugin.remove` is `Host.Remove` (`internal/pods/removal.go`): a per-id removing entry, the shutdown stop for one process, `TeardownMsg` (ignored without an entry or after the shutdown mark) and `RemoveDoneMsg`; the composition root's half (`Undeclare`, the `plugin` reload, tracked workers) is `Options.Remover`, implemented by `remover` in `internal/host/loop.go`. `internal/host.New` wires it; `cmd/husk` drives it through `Host.Frontend()`. Spec: `docs/docs/design/pods.md`.

Stale recovery has one implementation, `instance.RecoverStale` (`RecoverStaleWith` for test seams), used by the Server's claim and by the CLI's `Survey` and dial failure: `flock` `LOCK_NB` on a read-only descriptor of the runtime directory, retried every 50 ms to a 2.5 s deadline (`ErrLocked`, nothing removed, no blocking `flock`), a re-probe under the lock, then entry and socket removal; a path that is not a socket is refused (`*NotSocketError`). The lock is `syscall.Flock`, so `internal/instance` stays standard-library only. A socket the re-probe found missing is never unlinked. `instance.SocketIdentity` (`lstat` `(dev, ino)`) is taken right after each successful bind and passed to `Unregister`, which leaves a replacement socket and its entry alone. Tests inject `Deps.Ping` and `Deps.LockWait`; contention tests hold the lock on a second descriptor.

V2 socket/manifest changes use `go test -race ./internal/pods/... ./internal/instance/... ./pkg/protocol/...`. Server tests use private short temporary Unix socket directories, never the real runtime directory. Handler.Serve receives an explicit Notifier. Admission never blocks the reader: 64 active requests, 64 pending ordered notifications (including the active one); excess gets busy/too_many_in_flight, so EOF can cancel contexts. Socket output uses the injected queue watchdog through a write-only adapter: an injected clock's epoch is not a native socket deadline. instance.CheckRuntimeDir shares the existing directory rule; registration failure after bind is fatal. Only stale recovery takes an advisory directory-FD flock (`instance.RecoverStale`, O_RDONLY, no lock file), then re-probes before unlink/rebind; normal bind is lock-free. protocol.Message.HasToken distinguishes absence from a decoded empty credential. Reader diagnostics only update counters: coalesced Count/LastCode notices post from a worker at most once per second per connection, with one outstanding callback server-wide; a blocked loop never stalls readers or cleanup.

The standalone v2 Event bus is tested with `go test -race ./internal/stem/eventbus/... ./internal/host/ports/...`. `Publish`/`Flush` are loop-only (Flush at the end of each `Update`, after State); `Subscribe`, its cancel and `SetTable` are safe from any goroutine. It writes only through `contracts.Notifier` and reads liveness through an injected `Liveness` (checked at Publish). `ports/stem.Events` is the `event.emit`/`event.watch` port; its `Loop.Do` seam runs the publish on the loop. Spec: `docs/docs/design/message-kinds.md`.

The standalone v2 Dispatcher is tested with `go test -race ./internal/stem/dispatcher/... ./internal/host/ports/stem/...`. It is loop-confined: `Invoke`, `RegisterHost`, `Complete` and `List` run on the loop, and `Complete` receives the results Calls returns (Resolve, Expire, DropPlugin, Close). The catalog, liveness and focus are injected views (`DocCatalog` adapts declared `plugins` documents; `StateLiveness`/`StateFocus` read State snapshots); it never imports Store, Pods or Services. `internal/host/ports/stem.Calls` is the `CallsPort`: it posts onto the loop through an injected `Post` and waits off it. `internal/host.New` wires both; `cmd/husk` drives it through `Host.Frontend()`. Spec: `docs/docs/design/message-kinds.md`.

Host contracts live in `internal/host/contracts` (consumer-defined ports, launch seams, `Limiter`, `Config`/`Host`, `Occupant`/`Contribution`) with recording fakes in its `fakes` subpackage; test with `go test -race ./internal/host/...`. The package must not import Services or the Server (`TestImportsStayWithinAllowList`). Ports return `CodedError`; read the wire code with `contracts.CodeOf`, never the message. Fake clocks only, no sleeps.

The v2 host boots from `internal/host.New(contracts.Config)` (composition root; wiring only). It builds Store, State, Services, the Stem modules, Pods and the Server in dependency order, registers every adapter from `internal/host/handlers` (the `plugin.` prefix adapter is `handlers/plugin`), and exposes `Run(ctx)` and an idempotent `Close()`. The caller owns the Bubble Tea loop and feeds what `Config.Post` receives to `Update` on the loop goroutine. Test it with `go test -race ./internal/host/` (a real Unix socket in a private runtime dir, fake plugin processes, no sleeps); startup-failure cleanup is tested by failing each build stage through the unexported `afterStage` option. `cmd/husk` runs on this host through `Host.Frontend()`.

Services live under `internal/services/`, with shared contracts in the leaf `contracts` package and root aliases. `Rebuild(ctx, input)` prepares an unpublished candidate; only the coordinator applies it before the shared reload deadline. Public user-only exposure/mutation methods validate a verified Caller; Profile/grant writes are posted to the loop. Snapshots are immutable atomic-pointer publications. Services import no Stem/Pods or config filesystem implementation. Key spelling is shared through `internal/keyspelling`; `cmd/husk` still spells wire keys with its own `legacyKeyString`. Check Services with `go test -race ./internal/services/... ./internal/keyspelling/... ./pkg/theme/...`; tests inject clocks/dialogs/crypto and never sleep. A late reload request joins one queued follow-up after input capture, not an already-stale running flight. Plugin settings access (`Get` / `SnapshotFor`) is exact declared ownership plus public `husk.*`, never a subtree-prefix grant: plugin ids may contain dots and retain case; local setting keys are one lowercase segment. Caller kinds must be explicit (empty Caller is denied). Reload flight contexts belong to the coordinator, not any requester: cancelling a waiter must not cancel shared or queued work. Keymap last-good caches are profile-aware; disabled sequences never become prefixes.

## CLI

`husk <subcommand>` is a socket client of a running instance; no subcommand starts one. `cmd/husk/main.go` dispatches on a first argument that does not start with `-` with `os.Exit(cli.Main(ctx, args, cli.OSEnv()))` and installs no signal handler (it must not import `os/signal`: `TestMainInstallsNoSignalHandler`). The client lives in `internal/cli` (standard `flag`, no CLI library): `Main` parses the global flags (`--instance`, `--socket`, `--format`, `--timeout`, interspersed with positionals). `Invocation.Connect` resolves through `instance.Resolve` (explicit targets are never probed; only discovery surveys, 500 ms), dials, starts the `--timeout` context, and sends `session.ping` first on that one connection (`checkMajor`, exit 6). `Client` (`Dial`, `Call`, `Stream`) speaks `pkg/protocol` types only. A noun with verbs (`state get`, `action list`, `event watch`) carries them in `command.verbs`; command-specific flags (`--owner`, `--arg`, `--args-json`, `--data`, `--if-revision`, `--force`, `--action`, `--focus`, `--shadowed`, `--problems`, `--source`) are registered once in `Main` and each command lists what it `accepts`, so any other is exit 2 (`--force` is accepted only by `state clear`). `state`, `action`, `event` and `plugin` verbs are named wrappers in `cmd_state.go`, `cmd_action.go`, `cmd_event.go` and `cmd_plugin.go` (`plugin remove` has its own 10 s default timeout); the watches share `Invocation.watch` (`cmd_stream.go`: `Stream.Only` keeps the stream's own method, `command.stream` rejects `--timeout`, the 5 s opening bound rides `Conn.Ctx` and the stream itself runs on the unbounded context). `state set` and `state patch` take the request params as their JSON object (`slice` included); the CLI adds only `if_revision`. Local commands (`instances`, `store`) reject `--instance`, `--socket` and `--timeout`. Every failure is an `output.Error` with the spec's exit code (1 remote, 2 usage, 3 no instance, 4 ambiguous, 5 transport, 6 protocol, 7 environment) and a code from the closed set; `--format` governs stderr too. `internal/cli/output` is a leaf package (stdlib, `pkg/protocol` and `github.com/mattn/go-runewidth` only, `output/imports_test.go`) holding formats, errors, the table aligner and the generic rendering. A new command is an `output.Command` registered with `cli.Register(noun, cmd)` (registered commands are local; built-ins are `instances`, `ping`, `rpc`, `state`, `action`, `event`, `plugin`, `hook`, `keys`, `settings`, `theme`, `profile`, `secrets`, `config`); print through `output.Options`, never the process's stdout directly. `internal/cli` imports `output`, `internal/instance` and `pkg/protocol` from Husk and `golang.org/x/term` and nothing else (`TestImportsStayWithinAllowList`). The `store` noun (`paths`, `check`, `gc`, `reset-secrets`) is `internal/cli/storecmd`, the only command package that imports Store (plus `instance` and `output`, pinned by its own `TestImportsStayWithinAllowList`); `cmd/husk` wires it with `cli.Register("store", storecmd.Command())`. It opens Store with the directory `instance.LookupRuntimeDir` found or `""`, so no runtime directory is created (Store still creates config/state/data, store.md), and with `Options.Passive`, so `Open` runs no GC, quarantines nothing and writes no `meta.json` (a passive Open leaves a malformed one in place, unreported); explicit `GC` and `ResetSecrets` still act. `Store.ResetSecrets` deletes `secrets/*.age`, the keyring identity (through the injected `Keyring`, which now has `Delete`) and `identity.txt`, nothing else; `reset-secrets` refuses first while `Survey` finds a live or unresponsive instance. Tests use the fake keyring, never the OS one. Test with `go test -race ./internal/cli/... ./internal/instance/... ./internal/host/`: client and commands run against a fake socket server in a short private `/tmp` directory (`testkit_test.go`), and `internal/host/cli_e2e_test.go` runs the commands against a real host. Spec: `docs/docs/design/instances.md`.

Services commands are thin clients in one `cmd_<noun>.go` per noun: `settings get|list|schema|validate|set`, `theme show|roles|check|list|set`, `profile list|current|use`, `secrets list|set|grant|revoke|reveal`, `config reload`, and the read-only `keys` command. They call one method after the version ping with explicit params; semantic validation and authorization stay server-side. The default is 5 s, except `config reload`, `settings set` and `theme set` (10 s each). `cmd_services.go` shares positional validation and escaped tables; never import host or Services reply types into the CLI. Keys filters are client-side in both formats; `--problems` excludes `--action`/`--focus`. `settings schema --owner` is a verbatim server parameter. `secrets set` reads only stdin, strips one LF/CRLF and rejects malformed UTF-8 before connecting; terminal stdin uses `Env.StdinIsTTY`/`ReadPassword` (production: `term.ReadPassword`) with the prompt on stderr. Never print a secret in an assertion failure or reader error. `applied:false` and `ok:false` remain exit 0. The raw JSON results and the few fixed projections are documented in `instances.md`; custom tables use `serviceTable` and `output.Text`.

## Charm v2

- Import `charm.land/bubbletea/v2` and `charm.land/lipgloss/v2`; stable v2 uses these canonical vanity paths, not the old GitHub module paths. Bubbles is not currently used.
- `View()` returns `tea.View`: use `.Content` for headless frame output/assertions, and set `AltScreen` / `MouseMode` on the view rather than program options.
- Handle `tea.KeyPressMsg` separately from `tea.KeyReleaseMsg`; mouse click, release, motion and wheel events are distinct types implementing `tea.MouseMsg` (`.Mouse()` exposes coordinates).
- Keep the existing wire key spellings through `legacyKeyString`: Space is `" "`, NUL is `"ctrl+@"`, Alt precedes other modifiers (`"alt+ctrl+x"`), and printable shifted Alt keys use their text (`"alt+X"`). Native releases may omit `Text`; normalize `ShiftedCode` too so held keys clear. Ignore Num/Scroll Lock for matching, but retain Caps Lock for printable fallback casing. Decoder-backed tests include CSI-u lock modifiers and native releases. `tea.PasteMsg` retains v1's bracket-wrapped key spelling so pasted text cannot run host shortcuts; while the palette is open the paste goes straight to the query (`pastePalette`: line breaks and tabs become spaces, other control characters are dropped).
- `lipgloss.Color` is a function returning `image/color.Color`; styles are values and there is no global renderer or `SetColorProfile`. Bubble Tea handles interactive color downsampling; headless frame dumps retain full ANSI styling.
- Use `go build -buildvcs=false` for exported-source builds and the toolchain's `gofmt` binary if a PATH wrapper does not support `-l`.

## Layout

| Path | Purpose |
| :--- | :--- |
| `cmd/husk/` | Host workbench: slots, dock/palette, mouse resize, activity rail. A `contracts.Frontend` client of `internal/host`. Files: `main.go` (flags, `programRef` post gate, host construction), `dumpframe.go` (`--dump-frame`: a headless `tea.Program` that settles on Pod status and content, a quiet window capped by a maximum settle time, plus a context deadline; no second event loop, no sleeps. Exit contract, implemented by `dumpFrameMain` in `main.go`: the frame is always printed on stdout, and the process exits 1, with the cause once on stderr, when no plugin went live, on timeout, when `--rail` matches no loaded rail item, or when the host stopped; otherwise 0), `model.go` (model type, `Init`/`Update`, `refresh` from State, `flushState`, host actions, `modalOwner`/`surfaceOwner`), `keys.go` (`defaultKeys`, the no-host fallback keymap), `surfacemeta.go`, `input.go` (keys, mouse, drag), `commands.go` (rail buttons, palette, footer hints), `layout.go` (`recomputeLayout`, rects, frames, z-ordered hit order), `render.go` (`View` and helpers), `published.go` / `published_render.go` (published slots), `compose.go` (the cell canvas `View` draws into; `fillDefaultBg` paints the slot background under default-background cells), `demo.go` (`--demo-frame` / `--demo pubslots` fixtures only); `modifiers_darwin.go` polls Alt/Option via Quartz (see "Modifier polling" below) |
| `internal/substrate/state/` | V2 live JSON slice tree: owner handles, atomic copy-on-write snapshots, per-Update change listeners and preloaded Store hydration; standard library only. Initial core slice names and owners live in `initial.go`. Wire error mapping and user-only Clear authorization belong to the Server, not State. |
| `internal/substrate/store/` | V2 persistence mechanics: layered HuJSON, separate declared documents, private atomic local sources, lazy age/keyring secret namespaces, debounced retention and GC. Runtime/socket naming delegates to `internal/instance`. Secret values never go into State. |
| `pkg/protocol/` | The v2 wire package, standard library only and public for Go plugins: `Message` (request, reply, notification), method names (`methods.go`), params and result types with `Valid()`/`Validate()` (`params.go`, including the `FrameSpec` and `Palette` wire structs the host converts to `pkg/frame` / `pkg/theme`), `Version` and `CheckVersion` (`version.go`), the JSON-lines reader (`read.go`: reports malformed and over-4 MiB lines and keeps reading) and the non-blocking queued writer (`queue.go`: bounded queue, write deadline, disconnect on overflow/timeout; never write a socket synchronously from `Update`). `pkg/protocol/schema` generates `docs/docs/wire-schema-v2.json` |
| `internal/pods/manifest/` | `husk-plugin.json` parsing and conversion to the plain declaration catalog (see the pods paragraph below); the manifest is read-only for the rest of the host. There is no public manifest package |
| `pkg/theme/` | The single `Palette` (`Default()`): CharmTone hex roles from `charmbracelet/x/exp/charmtone`, and `SlotBackground` (`slot.go`), the slot content background derived from the canvas by a fixed Lab-lightness shift (lighter on dark, darker on light; exposed as `Palette.Slot`, wire key `slot_background`), with a WCAG contrast test (`contrast_test.go`) over every pairing the chrome draws, slot background included |
| `plugins/` | Out-of-process plugins, each a directory with a `husk-plugin.json` and its code; currently the reference pair `reference` / `reference-actions` (one Go binary in two roles: publisher with frame, inline slot, hook and event; contributor that fills the slot). Copy `plugins/reference` when starting a plugin; `plugins/reference/main_test.go` drives it over pipes, and the binary (`plugins/reference/reference`) is git-ignored. The module path is `github.com/hyperlab-sh/husk`; `pkg/protocol` is the wire package other Go plugins import (stdlib only), so keep it stable; `pkg/theme` is host-internal and plugins receive colours as the `protocol.Palette` wire struct |

Mouse drags start only on a drawn divider: `detectDividerAt` requires the cell to be on the border ring of a surface whose frame declares `border` and to fall in that divider's band, so the first row or column of an unbordered surface is content. Palette query input accepts any printable rune (`isPaletteText`) and backspace removes a rune. `key_state.held`/`held_keys` for ordinary keys are best effort: entries expire 320ms after the last press (`model.go`) unless the terminal confirmed key-release reporting (`View` sets `KeyboardEnhancements.ReportEventTypes` and `ReportAlternateKeys`, so a shifted symbol's release matches its press; a key held under layout text, such as AltGr's "@" or a dead key's "é", is matched to its release through `heldAliases`, because releases carry no associated text and arrive under the key-code name; `tea.KeyboardEnhancementsMsg.SupportsEventTypes()` lengthens the expiry to a 1s safety net and `KeyReleaseMsg` clears the key; `View` also sets `ReportAllKeysAsEscapeCodes` (flag 8), so where the terminal grants it Enter, Tab and Backspace releases clear immediately (`TestFlag8EnterTabBackspaceReleaseClearsHeldKey`); on a terminal that reports releases but not flag 8 they stay held until that 1s net (`TestUnreportedEnterTabBackspaceReleaseLapsesAtSafetyNet`); `ReportAlternateKeys` also fixes the chord spellings `alt+!` for Alt+Shift+1 and `ctrl+a` for Ctrl+ф, pinned by `TestKittyWireSpellingOfAlternateKeys`). The flag can fall back to false mid-session when the renderer re-queries. Under tmux, kitty flags are forwarded only on recent versions with `set -g extended-keys on`; otherwise the 320ms timer stays in charge. Only `modifiers` is authoritative.

`View` is pure: it reads the model and never writes it (`TestViewIsPure` deep-compares a rendered model with an unrendered twin). Derived UI such as the architecture explorer is built locally in the render function, never stored in `slotUpdates`; state changes belong in `Update`. `View` composes the frame on a cell canvas (`compose.go`, an Ultraviolet buffer serialized once at the end): bars, surfaces at their slot rects (reverse `hitOrder`), chrome, then the modal, toast and palette, each drawn in z order; the modal and the palette (not the toast) are each followed by `canvas.castShadow` (popup shifted +2 cols/+1 row, minus the popup, clipped; fg/bg of the cells beneath blended `popupShadowStrength` toward black, default colours resolved against Ink/Canvas, wide glyphs darkened whole, same rect once per frame). Every write parses its own string from a zero pen and is clipped to its rect, so a style a fragment leaves open stays on the cells that fragment wrote; never splice strings with `ansi.Cut` to compose. Published content is laid out (`layoutPublished`: rows, region rects, hits) and drawn separately (`publishedLayout.draw`); input routing reads only the hits. The canvas measures graphemes with `ansi.GraphemeWidth`, as the layout does, and a wide glyph crossing a clip edge is blanked. Slot content is clipped to the inner rect, never wrapped or scrolled (`surfaceContentLines`).

Layout: when the side panel is shown, `recomputeLayout` makes the header/stage rects `surfaceGutter` (1) cell narrower than the centre column and `View` leaves that cell unwritten (a blank canvas cell), so the panel starts at its own rect. The gutter is inert: it is in no slot rect, so clicks and wheel events on it reach no surface. The `sidepanel-width` divider band covers the centre's right edge, the gutter and the panel's left edge (the gutter cell itself is never a drawn border, so it starts no drag), so the drag works whichever side is bordered (`TestSidePanelDividerAcrossBorderCombinations`). The sidebar has no gutter: its rects are exactly `sidebarWidth` wide (`TestCharmV2MouseResizeLifecycle`).

Minimum terminal size is 84x24 (`minTermWidth`/`minTermHeight` in `layout.go`): below it `View` renders `renderTooSmall`, a frame that exactly fills the real terminal; `m.width`/`m.height` hold the real size and are never clamped.

Modifier polling: two sources report a bare modifier press. `View` sets `KeyboardEnhancements.ReportAllKeysAsEscapeCodes`, so kitty-protocol terminals (kitty, ghostty, wezterm, foot) send bare Shift/Ctrl/Alt/Super presses and releases as key events; `trackModifierKey` (`input.go`) folds them into `modifiers` (left and right tracked separately; Hyper/Meta dropped) and never forwards them as keys; Caps/Num/Scroll Lock presses, which terminals report only in this mode, are swallowed the same way. Because that mode stops terminals sending a key's text, `View` also sets `ReportAssociatedText`: text keys arrive as CSI-u with the produced text as a parameter, so AltGr symbols and dead-key or compose results keep their text (the key code alone would give the unshifted base key). `legacyKeyString` drops associated text from Ctrl/Super/Meta/Hyper chords so their names are unchanged, and `normalizeTextEvent` turns the spec's key-0 "pure text event", which the pinned decoder reads as ctrl+space, back into text. Bracketed paste is framed by the paste mode, not the keyboard flags. IME commits bypass the key encoder in kitty, foot and wezterm (plain UTF-8); ghostty sends them as plain UTF-8 or as CSI-u with associated text. That reading comes from the terminals' source, not from a session with a real input method. On darwin the OS modifier poll (`pollOSModifiers`) is also authoritative and overwrites the state on each tick; it is the only source on terminals without the protocol (Terminal.app, tmux). The poll runs every 40ms while a modifier, held key or input from the last 2s is active, every 150ms when idle, and not at all while the terminal is blurred. `View` sets `ReportFocus`, so `tea.BlurMsg` clears OS- and terminal-derived modifiers and held keys (broadcasting `key_state` up; a latched Alt from `?` or `--hold-alt` survives) and lets the tick chain lapse; `tea.FocusMsg` restarts it. Terminals without focus reporting never send `BlurMsg` and keep polling (under tmux, `set -g focus-events on` is required for blur gating). Where no OS modifier source exists (non-darwin), the chain lapses once no held key is pending and restarts on the next key press. Idle cost on darwin: a tick is about 0.32ms (the `View` rebuild dominates; the poll is about 31ns), so the 150ms idle rate is about 0.2% of one core; `BenchmarkIdleTickView` reproduces it.

Enumerated wire fields are named types with `Valid()`/`Validate()` in `pkg/protocol` (`SurfaceID`, `KeyPhase`, `Code`; `KeyStateParams`, `SurfaceKeyParams`, `Message`); they marshal as plain strings. Use the exported constants, not string literals.

Plugin processes: the Pods layer (`internal/pods`) launches them; stderr goes to the Store-owned log (`OpenPluginLog` in `internal/substrate/store`), and `cmd/husk` only shows what the host reports. Shutdown closes the post gate, then `Host.Close` (Calls, Server, Pods, Store).

Protocol versioning: `protocol.Version` is `"MAJOR.MINOR"` (currently `2.1`). There is no handshake: a plugin is identified by the credential the host gives it at launch. A manifest's integer `protocol` must equal `protocol.Major` (checked by `Spec.Validate` at conversion; a mismatched plugin is not launched). A plugin that still sends a v1 `hello` gets one v1-shaped `protocol_error` line, and its Pod fails with `version_mismatch`. `protocol.CheckVersion` validates a "MAJOR.MINOR" string for Go plugins. Minor bumps are additive only. Malformed JSON, mistyped fields, lines over 4 MiB and unknown methods get a `protocol.error` or a coded error reply and are logged; the connection stays open, and the host never answers a `protocol.error`. `pkg/protocol` imports the standard library only. Spec: `docs/docs/design/protocol.md`.

`cmd/husk` and the plugins speak `pkg/protocol`. After a v2 wire type change, run `go generate ./pkg/protocol` to refresh `docs/docs/wire-schema-v2.json` via `cmd/genschema`. Run affected tests with `go test ./pkg/protocol/...`. Queue tests inject `QueueOptions.Clock` rather than sleeping or using real timers. Spec: `docs/docs/design/protocol.md`.

## Conventions

- Husk core stays domain-agnostic: application-specific logic belongs in a plugin, not in `cmd/husk`. The host hard-codes no plugin command or rail item ID, no application key, and no application colour; keys reach plugins through rail item `shortcut` suggestions (bound in a keymap layer), the manifest's focus-local `keymap` bindings and focused-surface `input.key` (see `docs/docs/architecture.md`, "Input routing"). `TestHostSourceHasNoApplicationIdentifiers` guards the source and `TestDocsHaveNoApplicationResidue` guards the docs (README, SUMMARY, AGENTS, `docs/docs/*.md`), including that the documented surface count matches the registry.
- Start mode takes `--instance <name>` (validated by `instance.ValidName` before any filesystem access; invalid is exit 2, a given empty name included). `cmd/husk` resolves `instance.LookupRuntimeDir()` once without creating it; the root validates any bundle before calling `instance.CheckRuntimeDir` and gives the same string to the Server and to Store (`store.Options.RuntimeDir`; Store resolves nothing, and `""` means no instance is registered). The build version (`-ldflags "-X main.version=..."`, else the module version) reaches the entry and `session.ping` as `host_version` through `host.WithVersion`.
- Bundles load at start through `--bundle <dir>` or user/named-instance `husk.bundle` (restart-only). `internal/host` alone imports `internal/bundle`: its first stage runs `store.ReadBootstrap` and `bundle.Load` before any persistence/runtime creation. Bundle config is the second distribution-layer part (`Options.Bundle`), and its plugin directory loads last. Profile/distribution bundle settings are ignored with `bundle_setting_ignored`; no-plugin bundles log a warning, not a toast. Store never imports the bundle loader.
- Plugins are launched from the `husk.plugins.paths` / `husk.plugins.dirs` settings (read once at start from the startup flight's Settings snapshot; each entry interpreted like the matching flag value), with `--plugin` (executable, plugin dir, or `husk-plugin.json`) / `--plugin-dir` (scans immediate subdirectories) as the instance layer on top. There is no default plugin.
- Plugins must never assume a language; the JSON-lines protocol is the only contract. Additive changes (new optional fields or message types) bump the minor of `protocol.Version`; anything else is a major bump, which the host refuses for older plugins, so it means updating `pkg/protocol` and every plugin.
- Colour comes only from `theme.Default()`, whose roles are CharmTone hex values (truecolor; lipgloss downsamples on weaker terminals). Do not add other themes or literal colours in the host. Changing a role must keep `TestDefaultPaletteContrast` green (text 4.5:1, borders and non-text 3:1). `charmtone` is `x/exp` with a single v0.1.0 tag, so pin it.
- Conventional commits with detailed messages. No attribution trailers.
- `SUMMARY.md` is the design history; `README.md` is user-facing.

## Beads Issue Tracker

This project uses **bd (beads)** for issue tracking. The database is shared with a sibling project (Husk issues use the `husk-` prefix). Run `bd prime` to see full workflow context and commands.

### Quick Reference

```bash
bd ready              # Find available work
bd show <id>          # View issue details
bd update <id> --claim  # Claim work
bd close <id>         # Complete work
```

### Rules

- Use `bd` for ALL task tracking — do NOT use TodoWrite, TaskCreate, or markdown TODO lists
- Run `bd prime` for detailed command reference and session close protocol
- Use `bd remember` for persistent knowledge — do NOT use MEMORY.md files

**Architecture in one line:** issues live in a local Dolt DB; sync uses `refs/dolt/data` on your git remote; `.beads/issues.jsonl` is a passive export. See https://github.com/gastownhall/beads/blob/main/docs/core-concepts/sync-concepts.md for details and anti-patterns.

## Agent Context Profiles

The managed Beads block is task-tracking guidance, not permission to override repository, user, or orchestrator instructions.

- **Conservative (default)**: Use `bd` for task tracking. Do not run git commits, git pushes, or Dolt remote sync unless explicitly asked. At handoff, report changed files, validation, and suggested next commands.
- **Minimal**: Keep tool instruction files as pointers to `bd prime`; use the same conservative git policy unless active instructions say otherwise.
- **Team-maintainer**: Only when the repository explicitly opts in, agents may close beads, run quality gates, commit, and push as part of session close. A current "do not commit" or "do not push" instruction still wins.
